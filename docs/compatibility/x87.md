# x87 encoding coverage

The [implementation audit](x87-audit.md) covers numerical, exception and
integration limitations separately from this byte map.

Doslet classifies every D8–DF opcode/ModR/M pair before accessing an operand.
The public, allocation-free `doslet_x86::x87_decode::decode` returns an
instruction with its mnemonic and operands, a later-ISA instruction, or a
reserved encoding. `Instruction::pops()` records stack consumption;
`Instruction::implemented()` describes opcode support, not the supported
numeric range or complete exception behavior.

The map covers the documented 80387 instruction set. Of the 2048 byte pairs,
1620 select 387 instructions, 168 select P6/SSE3 additions, and 260 are reserved
under this policy. Memory addressing forms repeat an instruction for each
ModR/M mode and r/m field; these counts are not counts of distinct instructions.
Undocumented aliases and vendor extensions, including FFREEP, are deliberately
excluded. WAIT (9Bh) is a separate CPU instruction; waiting spellings such as
FINIT and FSTSW consist of WAIT followed by FNINIT or FNSTSW.

The source for the encoding layout is Intel's [instruction-set reference,
Appendix A, tables A-7 through A-22](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2d-manual.pdf).
Obsolete FNENI/FNDISI/FNSETPM encodings are compatibility NOPs on the 387.
DOSBox Staging's `src/fpu/fpu.cpp` is a secondary implementation comparison,
not the definition of reserved encodings or numerical precision.

Control/status words occupy two bytes. Environment images occupy 14 or 28
bytes; complete saved states occupy 94 or 108 bytes. The operand-size attribute
selects these layouts. The address-size attribute independently selects how to
locate the operand; 66h does not change a fixed real/integer operand width.

## Execution boundaries and verification

All basic arithmetic directions now have handlers, including non-popping
ST(i) destinations and signed int16/int32 memory arithmetic/comparisons.
These handlers reuse the retained 64-bit significand and guest rounding control;
integer sources do not pass through a rounded binary64 register copy.
All seven constant loads retain 64 significand bits, round according to RC
independently of PC, and neither raise precision nor set C1 for rounding.
Native x87 reference captures cover each constant in every rounding mode.
Finite FYL2X uses bounded integer range reduction and retained inputs, then
one pop. Native comparisons cover 540 cases with a two-representable-value
tolerance, not a complete-domain accuracy guarantee; see the audit for scope.
F2XM1 supports finite inputs in [−1, 1] using a bounded integer series that
preserves tiny inputs; 144 native cases use the same comparison tolerance.
Finite FSCALE preserves the significand and ST(1), truncating its scale toward
zero independently of RC. Its 300 native cases match retained values exactly;
unsupported result exponents and nonfinite operands remain explicit errors.
FCOM/FCOMP preserve retained precision. FFREE changes tags without moving TOP;
FTST compares ST(0) with zero without popping; signed zeros compare equal,
signed infinities retain their ordering, and NaNs follow FCOM's invalid-operation
handling. Integer flags and all stack values remain unchanged.
FINCSTP/FDECSTP rotate TOP without moving values or tags. FABS clears the sign
without rounding. Unmasked arithmetic exceptions retain the destination and
avoid popping under the existing explicit-error exception model.

Recognized but unimplemented instructions report `CpuError::X87Unsupported`
with the decoded instruction, byte pair and guest address. Later-ISA errors
also identify the ISA mismatch. Reserved encodings report `X87Reserved`.
Unsupported numeric inputs still report arithmetic errors. Numeric range,
subnormal, special-value and exception-delivery limitations remain as described
in [SPEC](../SPEC.md); a complete encoding map is not complete x87 emulation.

Tests check the ISA classification of all 2048 byte pairs and route each through
the CPU interpreter. Separate semantic cases exercise all register indices,
operand directions, pop forms, fixed integer widths, address/operand overrides,
retained-precision comparisons and stack-tag operations. They are synthetic CPU
tests and do not establish game compatibility.

```sh
cargo test -p doslet-x86 -p doslet-x87 --locked
```
