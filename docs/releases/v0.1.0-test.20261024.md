# Doslet v0.1.0-test.20261024

Experimental test build combining PRs [#2](https://github.com/prekucki/doslet/pull/2),
[#4](https://github.com/prekucki/doslet/pull/4) and
[#5](https://github.com/prekucki/doslet/pull/5), plus the native/browser v86
integration and display work.

## Downloads

- `doslet-v0.1.0-test.20261024-linux-x86_64.tar.gz`: desktop application,
  headless runner and web builder. Built on Ubuntu-compatible 24.04 with
  dynamically linked ALSA/udev libraries. Windows and macOS binaries are not
  included.
- `doslet-v0.1.0-test.20261024-web.zip`: static browser UI and reusable
  v86-capable Worker runtime. Serve over HTTP; do not open through `file://`.
- `SHA256SUMS`: checksums of both archives. Each archive contains `BUILD.json`
  with its source commit and includes license notices.

No commercial game files, saved games or MT-32 ROMs are bundled.

## Try it

Extract the Linux archive, then run:

```sh
./doslet --demo
./doslet --game /path/to/GAME.EXE --mode v86
./doslet --config /path/to/game.toml --mode simple
```

Game profiles can select `mode = "simple"`, `"aot"` or `"v86"` under `[game]`.
The native v86 module is embedded in the executable. The library configuration
window exposes the backend selection.

To package your own browser game, extract the web archive and pass its root
directory to the downloaded builder:

```sh
./doslet-web serve /path/to/game.toml --mode v86 --web-dist /path/to/web-runtime
```

`build` writes a static site; `serve` builds a temporary site and starts a local
HTTP preview. AOT mode requires supported translated entries. Creating a fresh
runtime with Trunk instead of `--web-dist` still requires the source checkout
and the pinned tools.

## Included changes

- Batched x87 execution and exact host-float fast paths, DOS child processes,
  inherited handles, DPMI re-entry and divide-error dispatch.
- Sound-card selection and macOS system-mixer support in source.
- Game configuration/global settings, display shapes, fullscreen, RAVU,
  compact toolbar/status bar and CRT scanlines.
- Native and browser v86 backends with Doslet devices, host-clock IRQ/audio
  scheduling, keyboard wakeup and disabled-gameport probing.
- Portable `doslet-web --web-dist` use outside the build machine's checkout.

## Verification and limits

The merged tree passed 2,007 workspace tests and two additional v86 regressions
for DOS EXEC and successive DPMI children. Formatting, Clippy and release native
and WASM builds passed. Isolated Firefox checks covered MIDI/PCM output,
storage/HTTPS, translated v86/AOT execution and pause/reset. These checks do
not establish audible quality on physical outputs or full-game compatibility.

The 106 ignored workspace tests require separate fixtures or opt-in runs.
macOS system-mixer support has not been tested on macOS in this release run.
The earlier [release audit](../release-readiness.md) records additional
renderer checks and the pre-merge evidence.

Known limits:

- ROTT with its joystick enabled can override arrow-key input under v86.
  Disable the in-game joystick or the Doslet gameport until timing is fixed.
- v86 browser performance remains experimental; translated execution counters
  do not prove playable frame rates.
- Chromium WebGL uses a simple-filter fallback for RAVU to avoid the reported
  wgpu alignment panic.
- v86 portable state saving and GDB/instruction tracing remain unsupported.
- Portable state output is now version 5 because it records DOS processes;
  the loader retains support for versions 1 through 5.

## Rebuild the archives

After the native and Trunk builds, from a clean checkout of the release commit:

```sh
cargo metadata --locked --offline --format-version 1 --filter-platform x86_64-unknown-linux-gnu > target/release-metadata.json
python3 tools/package_test_build.py v0.1.0-test.20261024 --metadata target/release-metadata.json --web-dist web/dist --output target/test-release
```

The output directory must not exist. The script packages only the explicit
binaries, Trunk distribution and dependency license notices; it does not walk
game directories or user profiles.
